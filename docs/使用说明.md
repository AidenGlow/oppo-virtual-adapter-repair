# OPPO互联占用虚拟网卡修复 v1.11.0（发布版）

平台：Windows 10/11 x64（64 位）；单文件原生 Windows EXE，使用 Go 编译，不需要安装 Python 或 Go。

项目针对安装 OPPO 互联后开启代理 TUN 即断网的一类兼容性问题。案例、可能的网络机制和两种方式的作用见 [原因说明](原因说明.md)。

**软件不是 OPPO、Clash 或 Mihomo 官方工具。** 两种修复方法来自社区排障思路，不保证适用于所有软件版本与网络环境。请先保存工作、备份重要数据。

## 下载后怎么使用

双击 `OPPO互联连接修复工具_v1.11.0.exe`，Windows 会自动弹出管理员授权窗口，确认后进入界面。取消系统授权则程序不启动；文件修改仍需在工具内最终确认。

普通账户需要电脑管理员授权。若使用另一管理员账户授权，请手动指定原账户的代理配置并核对完整路径。软件没有代码签名，因此 Windows SmartScreen 可能显示“未知发布者”。本工具不自动访问外网；点击“检查是否生效”时只读取本机控制接口。不安装驱动，不改 Windows 系统的 DNS、路由表或全局代理。

v1.9 的“恢复 YAML 备份”会自动列出当前所选配置同目录的对应备份，按备份时间从新到旧排列，由你选择并最终确认后恢复。未选配置或没有匹配备份时会明确提示，始终保留“手动选择文件…”备用入口。打开列表、刷新和取消不会修改文件。继续使用现代控件、一体式标题栏和 680×524 DIP 的紧凑主窗口。**选择修复方式后，按钮会持续显示绿色底、白色文字，直到切换到另一方式，失去焦点或重绘不会取消高亮。** 保留高 DPI、两行问题 / 恢复提示、两种方式自主选择、手机勾选、手选网卡、备份与最终确认。

继续以自动定位为主要流程：第一种自动查找 OPPO 的 DLL；第二种选择 Clash Verge Rev 或 Clash for Windows，配置位置由工具识别，无需自行寻找 YAML。两种方式独立使用，无需依次执行。保留 Go / Win32 原生架构、手机连接确认、手选网卡、最终确认、备份与独立恢复。文字报告见 [版本说明](版本说明_v1.11.0.md)，验证明细见 [TEST_RESULTS.md](../TEST_RESULTS.md)。

### 遇到失败时怎么办

| 提示 | 下一步 |
| --- | --- |
| 权限不足或访问受限 | 确认已获得 Windows 管理员授权；已授权仍失败时，请管理员检查目标文件 / 文件夹的安全权限、只读状态或安全软件拦截记录。 |
| 文件被占用 | YAML：完全退出代理客户端及托盘、关闭编辑器和其他修复工具后重试。DLL：处理占用程序；OPPO 后台持续占用时可保存工作并重启后按手机连接前提重试，或选择 Clash / Mihomo 配置方式。 |
| 路径已失效或不可用 | DLL 点击“重新查找”或“手动选择”；YAML 点击“重新识别”或“手动指定”。恢复时核对原文件与备份的位置。 |

文件占用相关失败会只读查询 Windows，显示能识别到的程序名称、PID，以及可用的服务名。请先保存该程序中的工作，再正常退出或关闭托盘后重试；后台服务交由管理员处理。工具不会强行结束进程。查询有时限，超时、无法读取或未识别到程序会明确提示，这些结果不能证明文件没有被占用。

提示会保留相关路径、Windows 错误码及原始错误，方便反馈。DLL 的“拒绝访问”可能还需排查加载占用，不能仅凭该错误认定缺少管理员权限。已建立的备份路径会继续显示。

### 方法一：OPPO 互联 daemon 文件中的 DLL 改名/恢复

> **先在 OPPO 互联电脑版登录账号、确认自己的手机已经成功连接到电脑并保持连接。** 如果未连接就修改该 DLL，后续可能不能连接；修改后也可能暂时无法连接新设备。本工具不能自动判断手机是否已经成功连接，因此需要本人勾选确认。

1. 在主界面选择“OPPO DLL 修复”，工具会在后台从 Windows 安装记录、运行中程序和常见安装目录查找 `daemon\wintun.dll` 及其已改名文件，支持安装记录中的自定义盘符和路径。找到一处时自动填入；多处时由你在列表中选实际安装目录。找不到时可先启动 OPPO 互联再点“重新查找”，或用“手动选择…”兜底。自动查找只读，不执行修复，也不替你勾选手机连接。
2. 在 OPPO 互联保持登录、手机保持连接，勾选确认项，点击“修复 DLL”。
3. 阅读最后确认窗口，点击“是”后将该文件更名为 `wintun.dll.oppo互联`。已经存在该目标文件时程序拒绝覆盖。
4. 改名后必须重启 Windows，程序会询问是否立即重启，允许暂缓自行重启。
5. 需要恢复时，在同一个目录选中 `wintun.dll.oppo互联`，点击“恢复 DLL”，最终确认后恢复为 `wintun.dll`。**恢复后也必须重启电脑。**

本工具不扫描全盘、不批量处理同名文件。检查指定文件名和父目录，拒绝路径中的目录联接、符号链接或重解析点，并解析 PE 检查 DLL 属性与节区范围。有效 DLL 仍不能证明安装目录属于 OPPO 互联，请自行核对真实安装目录。改名使用 Windows 不覆盖目标的操作，目标冲突即停止。

### 方法二：Clash/Mihomo TUN 物理出站网卡修复

> 方法二修改的是 Clash/Mihomo 客户端的 YAML 配置，不是 OPPO 互联内部配置。

1. 在主界面选择“② Clash / Mihomo 配置”，工具会自动识别 **Clash Verge Rev** 和 **Clash for Windows** 的配置位置。在下拉列表选择你正在使用的软件；只找到一份可用配置时会自动填入，找到多份时由你选择。修复前请**完全退出所选代理软件，包括托盘程序**，完成后重新打开，避免客户端内存中的旧设置覆盖文件。通常无需点击“手动指定…”；它只用于特殊目录、其他客户端或无法识别的情况。
2. 点击“扫描并选择网卡”，出现独立的网卡列表。扫描在后台进行，等待时可以取消或关闭；窗口关闭后会取消任务，并丢弃过期结果。软件通过 Windows PowerShell 的 `Get-NetAdapter -IncludeHidden` 和 `Get-NetRoute` 获取网卡。默认只显示已连接的物理网卡；点击“显示全部”可查看其余网卡。只有唯一候选同时具备明确硬件属性、已连接状态和有效 IPv4 默认网关时，才显示“建议选择”和理由；多出口不猜测。**不自动选择第一张或推荐网卡**；筛选 / 刷新均清空选择。
3. 根据名称、设备说明、Windows 报告的硬件/虚拟属性、连接状态、接口索引、MAC 地址以及默认路由线索自行判断。使用 Wi-Fi 上网时一般选择 Wi-Fi 硬件网卡；使用网线时一般选择“以太网”硬件网卡；Clash、Mihomo、Wintun、TAP、VMware、Hyper-V 等通常是虚拟网卡，通常不要选。**仅有默认路由或显示已连接并不能证明它就是真实物理联网网卡。** 可从 Windows 的“设置 → 网络和 Internet → 高级网络设置”交叉核对。
4. 单击候选网卡查看详细信息，点击“选定并进入最终确认”。程序会再次展示网卡、YAML 文件路径及修改内容，对虚拟或未连接网卡追加警告。只有点击最后确认窗中的“是”，程序才会开始修改；点击“否”或关闭窗口不会修改 YAML。
5. 程序先保存文件备份 `原文件.oppo-backup-日期.bak`，并在备份旁保存 `.bak.oppo-repair.json` 网卡撤销记录，然后调整：

   ```yaml
   interface-name: "用户刚刚选中的物理网卡名称"
   tun:
     auto-detect-interface: false
   ```

   其中 `interface-name` 是**顶层配置**；`auto-detect-interface` 在 **`tun` 节点下面**。`tun.device` 不是物理联网网卡名称，程序不会修改它。程序解析 YAML 节点定位两个字段，在原始文本上局部修改；写入前重新解析候选结果，检查字段类型、网卡名称和其他配置语义。如果已经是相同配置，会提示无需修改，不生成新备份。
6. 修改成功后重新打开所选代理客户端，使其重新读取配置。Clash Verge Rev 的扩展脚本等仍可能覆盖网卡字段；Clash for Windows 的订阅刷新可能重置当前配置修改，需要重新修复或在客户端设置持久覆写。
7. 需要撤销时，先完全退出代理客户端，选择对应配置，再按下表选择范围。两种入口都自动按备份时间倒序列出当前配置的记录，不默认选中；刷新、预览和取消不会写文件。始终保留“手动选择文件…”入口。

| 按钮 | 恢复范围 |
| --- | --- |
| **只撤销网卡设置** | 只还原本工具当次实际改过的 `interface-name` 和 `tun.auto-detect-interface`；后来修改的节点、规则、密码和其他设置保留。先选原修复记录，核对字段预览，再最终确认。 |
| **恢复 YAML 备份** | 按备份原始字节还原整份配置，会覆盖备份之后的节点、规则等修改。保留旧版备份兼容。 |

两种操作都会在写入前另存当前配置保护备份，并重新核对当前文件、原备份及预览快照；确认后文件变化会中止。完成后重新打开代理客户端。

**只撤销网卡的条件：**原 `.bak` 和对应的 `.bak.oppo-repair.json` 必须一起保留在原配置旁。记录只包含格式版本、网卡名及原备份 SHA256，不复制节点、规则或密码，也不依赖旧 EXE。工具只在被还原字段仍等于当次修复写入值时撤销；字段已被再次修改、记录损坏或不匹配、当前 YAML 不能安全局部编辑时，停止并说明原因，不猜测或覆盖。只撤销成功后再次选同一记录，会提示已撤销或存在变化。

v1.10.0 及更早的备份没有撤销记录，不能直接做局部撤销，可继续使用“恢复 YAML 备份”。整份恢复前请核对覆盖范围。

### 检查修复是否生效

1. 完成配置修复后，重新打开所选代理客户端并启用 TUN。
2. 返回工具，保持选择同一客户端 / 配置，点击“检查是否生效”。无需退出客户端；修复与恢复操作仍要求先退出。
3. 在“执行结果”中查看检查结论：

| 结果 | 含义与下一步 |
| --- | --- |
| 配置已生效（当前运行内核） | 运行内核返回的网卡与所选设置一致、自动出口关闭且 TUN 开启。再打开常用网页确认实际联网。 |
| 网卡设置已采用，TUN 尚未开启 | 客户端已经采用网卡设置；请开启 TUN 后再次检查。 |
| 运行设置与修复设置不一致 | 内核仍使用不同的网卡或自动出口。先重载 / 重开客户端，仍不一致时检查扩展配置或脚本。该结果不直接断定是哪一层覆盖。 |
| 尚未加载 | 未发现运行中的代理内核，请打开所选客户端后重试。 |
| 无法确认是否生效 | 无法唯一匹配内核、本机接口未开放 / 无法认证、内核缺少检查字段，或检查期间配置变化。请按提示重新识别，或在客户端查看运行配置。不会把读不到结果判定为修复成功。 |

检查只读当前配置及与其对应的内核信息，通过本机 HTTP `GET /configs` 或 Windows 本地命名管道获取运行字段。核对内核 PID、启动时间、配置位置和控制端口 / 管道归属；HTTP 不使用系统代理、不跟随跳转，也不连接远程控制地址。密钥只用于本机认证，不显示或写入日志。不会自动开启 API、切换 TUN、重载配置或探测外网站点。

手动指定的 YAML / Merge 只在能够与内核实际运行文件精确对应时才可确认；无法对应时明确提示。检查确认的是全局出口 / TUN 设置已被内核采用，不代替真实网页联网验证，也不验证每个节点的单独出口覆盖。

配置机制参考：[Mihomo 运行配置 API](https://wiki.metacubex.one/api/#configs)、[Clash Verge Rev 配置优先级](https://www.clashverge.dev/guide/extend.html)。

### 可能遇到的问题与恢复

| 方式 | 可能遇到的问题 | 如何恢复 |
| --- | --- | --- |
| DLL 修复 | 手机连接失败、无法连接新设备；OPPO 更新后可能需要重新修复。文件被占用或权限不足时会停止并提示。 | 如遇问题可点击恢复。重新找到原安装目录里的已改名 DLL，点击“恢复 DLL”，完成后重启 Windows。 |

### 删除本工具后，重新下载还能恢复吗？

**可以，恢复不依赖旧 EXE、运行记录或安装状态，取决于原文件和备份是否仍在。**

- DLL 方式只把 `daemon\wintun.dll` 改名为同目录的 `wintun.dll.oppo互联`，原始文件字节保留。重新下载后查找或手动选择该文件，再点“恢复 DLL”。如果原名和改名文件同时存在，工具会停止，避免覆盖。
- 配置方式在原配置旁创建 `原文件名.yaml.oppo-backup-日期-时间.毫秒.bak`（`.yml` 同理）。重新下载后进入配置方式，选当前客户端 / 配置，再点“恢复 YAML 备份”即可自动列出；没有选择当前配置时，仍可用“手动选择文件…”恢复，不要求先选网卡。备份名称不带工具版本号。只撤销网卡还需对应的 `.bak.oppo-repair.json`；在同一配置的“只撤销网卡设置”入口选择原修复记录即可。旧版只有 `.bak` 时可整份恢复。
- **仅删除本工具 EXE 不会删除这些文件。请保留原配置、备份文件及所在目录。** 当前恢复逻辑要求目标 `.yaml` / `.yml` 仍然存在，按备份文件名确定同目录目标。如果只把 `.bak` 搬到下载目录，需先放回原配置旁。
- 如果备份 / 已改名 DLL 被清理，或重装 OPPO / 代理软件时原目录被覆盖或删除，本工具不能凭空找回旧内容。多次修复有多份备份时，请选对应修复前的那份。“恢复 YAML 备份”会还原整份文件；“只撤销网卡设置”只还原有记录且未冲突的网卡字段；两者都另存当前配置保护备份。

### 清晰度与窗口大小

清晰度取决于按显示器 DPI 重新绘制字体和控件；窗口大小由布局单独管理。本版在 DPI 改变时重新创建原生 ClearType 字体并重新布局。100% / 125% / 150% / 200% 已通过 GDI 字体及文字尺寸回归，本机 200% 实际 EXE 已检查；其他显示器组合仍待实测。参见 [微软高 DPI 说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) 和 [DPI 声明建议](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)。

### 两种客户端如何识别

- Clash Verge Rev：识别用户数据目录中的 `verge.yaml` 和持久程序配置 `config.yaml`，不把 `clash-verge.yaml` 等生成文件作为自动修改目标。默认目录为 `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev`，也探测已识别的程序 / 内核数据目录。
- Clash for Windows：默认检查 `%USERPROFILE%\.config\clash`，同时检查 `CFW_HOME`、已识别的程序与便携数据目录；读取 `profiles\list.yml` 的 `index` 和 `files[].time`，定位当前启用的配置。尚未启用、索引无效或文件缺失时只提示，不猜测第一份文件。
- CFW 没有当前配置时，请先在客户端 Profiles 中启用一份配置，再退出客户端并点“重新识别”。识别后若切换了当前配置，最终修复前的核对会中止旧目标。
- 自动识别和扫描均在后台运行；切换方式或关闭窗口会取消，过期结果不会覆盖新选择。自动识别不会关闭客户端或改写配置。

### YAML 支持范围与恢复条件

- 编辑支持 UTF-8（含 BOM）、单文档块映射、普通块形式的 `tun`，以及单引号或双引号包围的目标键。已有子项按实际缩进插入，覆盖 1 / 2 / 4 / 8 空格测试；空块或缺失 `tun` 使用两空格缩进。
- 保留原有注释、UTF-8 BOM、每行的 LF / CRLF 和末尾是否有换行；无关配置中的行内集合、块字符串等保持原始文本。支持单文档的 `---` / `...` 标记。
- 拒绝重复键、语法错误、多文档、根序列或标量、非字符串映射键、锚点、别名、合并键、自定义标签、行内根或行内 `tun`，以及目标字段的块标量、跨行值等无法安全局部编辑的表示。拒绝发生在建立备份和写入之前。
- 现有 `interface-name` 必须是字符串或空值；`tun.auto-detect-interface` 必须是布尔值或空值。编辑结果中两者分别是所选网卡名称和布尔值 `false`。这项校验不代替 Mihomo 配置模式校验，也不能判断客户端最终采用哪个配置层。
- 恢复目标必须是仍然存在的普通 `.yaml` / `.yml` 文件，不接受 `.txt`、`.exe` 等类型或备用数据流。备份名称须匹配本工具的时间戳后缀，内容须能解析为有效的单文档 YAML 映射且没有重复键；当前目标即使已损坏，也可以用有效备份恢复。
- 恢复按备份原始字节写回，允许有效的旧版行内映射或锚点配置；这些表示仍不支持自动编辑。备份文件名和解析成功不能证明来源，请核对确实是自己的配置备份。YAML 编辑和恢复均使用临时操作锁、阻止其他新写句柄，并核对文件身份、内容及备份快照。Windows 文件替换会保留原 DACL，备份也显式保留访问规则及继承保护；权限保留失败则停止。提交前释放读取句柄的短暂窗口仍不能完全排除外部替换竞争。

## 从源代码编译

安装 Go 1.23 或更新版本，在管理员终端进入 `source/` 目录后运行；测试 EXE 同样包含提权声明。随包固定依赖为 `go.yaml.in/yaml/v3 v3.0.5`，使用 `vendor/` 可以离线构建。`source/app_windows_amd64.syso` 已随源码提供并自动链接，包含 DPI 与 Windows 兼容性 manifest。修改 `app.manifest` 后，先运行 `go generate .` 重新生成资源；生成器只使用 Go 标准库。

本次交付使用 Go 1.27.2；没有用 Go 1.23 工具链复测。

```powershell
$env:GOOS="windows"
$env:GOARCH="amd64"
$env:CGO_ENABLED="0"
go build -trimpath -mod=vendor -ldflags="-H windowsgui -s -w" -o "..\OPPO互联连接修复工具_v1.11.0.exe" .
```

在 Windows 上运行回归测试与静态分析：

```powershell
go test -mod=vendor -count=1 ./...
go vet -mod=vendor ./...
go test -mod=vendor -run '^$' -fuzz '^FuzzYAMLEditIsSafe$' -fuzztime=10s -parallel=2 .
```

GUI 线程测试使用临时隐藏窗口，文件处理测试只操作临时目录。普通 `go test` 不会修改真实 OPPO 安装文件、重启电脑或改变系统网络设置。
